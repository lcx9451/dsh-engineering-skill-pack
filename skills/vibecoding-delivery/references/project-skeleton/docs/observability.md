# 可观测性规范

| 项 | 值 |
|---|---|
| 最后更新 | <YYYY-MM-DD> |
| SLO 目标来源 | `docs/PRD.md` 第 7 节（可用性、P95） |

## 一、日志（结构化，JSON）

**必带字段**：

| 字段 | 说明 |
|---|---|
| `timestamp` | ISO-8601，UTC |
| `level` | trace / debug / info / warn / error |
| `funcName` | 产生日志的函数名（便于按调用链检索） |
| `traceId` | 链路 ID，跨服务与异步任务透传 |
| `spanId` | 当前 span |
| `durationMs` | 有耗时语义的操作必带 |
| `errorType` | 出错时的错误类名（不是 message） |

**禁止**：

- `console.log` / `print` 裸输出（除本地临时调试，提交前必须删除）
- PII：姓名、手机、邮箱、身份证、地址、简历正文
- 完整请求体/响应体、完整 SQL 及参数值、任何密钥或 token
- 把异常对象直接序列化（可能带出上下文中的敏感字段）——只记录 `errorType` + 脱敏后的 message

## 二、链路追踪

- 使用 OpenTelemetry，服务名与版本随部署注入
- 上下文必须跨**异步任务与队列**透传（消息体携带 `traceId`）
- 关键外部调用（DB、第三方 API、队列）必须有 span，并标注目标与耗时
- 采样：开发 100%，生产按 <10>% 基础采样 + 错误全采

## 三、指标

| 类型 | 指标 | 说明 |
|---|---|---|
| RED | Request rate / Error rate / Duration（P50/P95/P99） | 每个对外端点 |
| USE | Utilization / Saturation / Errors | CPU、内存、连接池、队列深度 |
| 业务 | <处理成功率、平均处理时长、待人工队列长度> | 对应用户可感知的健康度 |
| 依赖 | <第三方调用成功率与耗时> | 用于判断是谁的问题 |

## 四、SLO 与错误预算

| SLI | 目标（SLO） | 测量窗口 | 错误预算 | 预算耗尽的动作 |
|---|---|---|---|---|
| 可用性 | <99.9%> | 30 天滚动 | <43 分钟> | **冻结功能发布**，转入稳定性工作 |
| 成功率（业务） | <≥99%> | 7 天滚动 | <…> | <暂停灰度，回滚> |
| 延迟 | P95 ≤ <500>ms | 7 天滚动 | <…> | <优化或扩容> |

> 错误预算的作用是**让"要不要继续发版"有客观依据**，而不是靠争论。

## 五、告警

规则：**只对用户可感知的症状告警**，每条告警必须有 runbook 链接和明确的第一个动作。

| 告警 | 条件 | 级别 | 首个动作 | Runbook |
|---|---|---|---|---|
| 可用性下降 | 5xx 比例 > <1>% 持续 5 分钟 | P1 | <回滚上一版本> | <链接> |
| 延迟劣化 | P95 > <800>ms 持续 10 分钟 | P2 | <看 DB 慢查询与队列深度> | <链接> |
| 队列积压 | 深度 > <1000> 持续 15 分钟 | P2 | <扩容 worker / 查第三方限流> | <链接> |
| 错误预算耗尽 | 30 天窗口消耗 > 100% | P2 | <先修稳定性，暂不加新功能> | <链接> |

- 禁止无动作告警；新增告警必须同时提交 runbook
- 告警噪音治理：每月复核，长期无动作的告警删除或降级

## 六、验收方式（对应 Step 17 退出标准）

- [ ] 本地起服后，能在面板里看到一个请求的完整链路（入口 → core → DB → 外部调用）
- [ ] 人为制造一次错误，仅凭日志就能定位到函数与具体请求
- [ ] 制造一次慢查询，能在延迟指标上看到，并触发预期告警
- [ ] 抽查 3 条日志，确认无 PII
