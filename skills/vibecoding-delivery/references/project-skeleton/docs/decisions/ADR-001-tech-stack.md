## Decision

采用 **<TypeScript + Node.js 22 LTS + PostgreSQL 16 + Prisma + Fastify>**，锁定版本见 `docs/tech-stack.md`。

## Alternatives Considered

### <Python + FastAPI>

- Pros：<数据处理生态强；团队有人熟悉>
- Cons：<类型检查依赖 mypy，运行时校验需额外投入；与前端共享类型困难>
- Rejected：<本项目领域逻辑以表单/状态流转为主，共享类型带来的收益更大>

### <函数计算 / Serverless 优先>

- Pros：<零运维、按量计费>
- Cons：<长时批量任务受执行时长限制；冷启动影响 P95>
- Rejected：<批量解析单次可能超过执行上限，需要常驻 worker>

## Consequences

**正面**：

- 前后端共享类型定义，接口漂移可由 `tsc` 机械拦截
- 单测/集成/E2E 工具链成熟，符合"越可验证越好"
- PostgreSQL 托管选项多，退出成本低

**负面 / 需要接受的代价**：

- 需要自建常驻 worker 处理批量任务，多一个部署单元
- Node 生态依赖更新频繁，需要每月依赖巡检

**需要后续跟进**：

- 补 ADR-002：鉴权方案（会话 vs JWT）→ 阻塞 `<api>` 模块开工
- 补 ADR-003：异步任务载体（数据库队列 vs 消息中间件）→ 阻塞 `<worker>` 模块
- `docs/risks.md` 登记 R3：团队 K8s 经验不足 → 采用托管容器

## 推翻本决策的成本

<语言层更换 ≈ 全量重写，代价极高，因此本决策在 Gate 2 之前必须定稿。
数据库更换：ORM 隔离了大部分 SQL，迁移工作量中等（预估 <2 周）。
框架更换：路由与中间件需重写，核心领域逻辑可复用，预估 <1 周。>
