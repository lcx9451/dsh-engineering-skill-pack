# 测试策略

| 项 | 值 |
|---|---|
| 最后更新 | <YYYY-MM-DD> |
| 覆盖率门槛来源 | `docs/CONSTRAINTS.md` 第二节 |

## 一、测试层次与配额

| 层次 | 覆盖什么 | 数量级 | 单次耗时 | 跑在哪 |
|---|---|---|---|---|
| 单元测试 | 纯领域逻辑、校验、边界与异常分支 | 多（数百） | <10s 总量 | 每次编辑 / CI |
| 集成测试 | 模块间协作、DB 读写、事务、幂等 | 中（数十） | <60s | 任务结束 / CI |
| 契约测试 | 实现与 `openapi.yaml` 一致 | 每端点 ≥1 | <30s | CI |
| E2E | 核心业务闭环（≤5 条主流程） | 少而稳（5–15） | <5min | CI（预览环境） |
| 压测 / 故障注入 | NFR 数字（P95、峰值、降级） | 按需 | 分钟级 | Gate 5 |

**原则**：越靠下的层次越贵越脆。能用单元测试证明的，不要写 E2E。

## 二、覆盖率口径

- **强制口径 = 变更行覆盖率 ≥ 80%**（`diff-cover` 对比目标分支）
- 项目整体覆盖率只做**棘轮**（记录当前值，不得下降），不用来卡新 PR
- 覆盖率不是目标本身：**断言质量**优先。核心领域逻辑引入变异测试，起点 60%
- 禁止为了覆盖率写"只调用不断言"的测试

## 三、每类改动的最小测试要求

| 改动类型 | 必须新增/更新 |
|---|---|
| 新增业务函数 | 单元测试：正常路径 + 每条异常路径 |
| 新增/修改 API | 契约测试 + 集成测试（含 401/403/404/429 至少各一） |
| 修改 DB schema | 迁移正向 + 回滚（或前向修复）脚本测试 + 集成测试 |
| 修复 Bug | **先写能复现的失败测试**，再修，测试必须留在仓库 |
| 修改并发/幂等逻辑 | 并发重复提交测试 |
| 权限相关 | 越权测试（横向 + 纵向） |
| 新增第三方集成 | 契约/桩测试 + 超时与重试路径测试 |

## 四、测试数据与确定性

- [ ] 统一工厂/fixture 管理（`test/factories/`），禁止复制粘贴测试数据
- [ ] **禁止依赖生产数据快照**；需要真实形态数据时用脱敏样本，且不含真实 PII
- [ ] 时间、随机数、时区、UUID 一律可注入（`Clock` / `IdGenerator`），禁止直接调系统时间
- [ ] 禁止 `sleep` 等异步：用可控时钟或事件等待
- [ ] 网络与第三方调用在单元/集成层一律打桩；只有 E2E 与契约测试允许真连（指向 sandbox）
- [ ] 测试之间相互独立，可任意顺序、可并行执行

## 五、Flaky 处理

- Flaky 测试**视为缺陷**，登记到下表并限期修复；禁止靠"重跑"放行
- 连续两次无改动失败 → 立即上浮为 P2

## 六、命令

```bash
pnpm test            # 单元 + 集成
pnpm test:coverage   # 带覆盖率
pnpm test:changed    # 只跑受影响文件
pnpm test:e2e        # 预览环境上跑（CI）
```

## 七、AI 生成代码的测试纪律

- `implementation-plan.md` 每步声明的测试项**没有完成，该步视为未完成**
- 禁止 AI 同时"写实现 + 放宽断言"来通过测试；评审重点看断言是否变弱
- 新增 `.skip` / `.only` / 删除测试文件，必须在提交信息里给出理由，否则视为违规
