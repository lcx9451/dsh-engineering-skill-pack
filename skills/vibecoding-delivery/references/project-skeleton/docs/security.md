# 安全工程规范

| 项 | 值 |
|---|---|
| 最后更新 | <YYYY-MM-DD> |
| 合规依据 | `docs/PRD.md` 第 8 节 |
| 机械检查 | 见 `docs/CONSTRAINTS.md` 第二节 |

> 原则：**每一项安全要求都要能落到一条命令或一个测试上**，否则它只是形容词。

## 一、密钥与凭证

- [ ] 一律由 Secret Manager / KMS 注入（本地用 `.env`，且 `.env` 不入库）
- [ ] 仓库与历史全量扫描：`gitleaks detect --redact --no-banner`（**必须带 `--redact`**：否则命中值会被打印进日志与 AI 上下文）
- [ ] 密钥有轮换周期（建议 ≤90 天）与吊销流程；轮换步骤写进 runbook
- [ ] 最小权限：服务账号只授予运行所需权限；CI token 只读
- [ ] 禁止把密钥写进镜像层、前端产物、日志、错误上报

## 二、输入与输出

- [ ] 所有外部输入在边界做 schema 校验（类型、长度、枚举、范围、文件类型与大小）
- [ ] SQL 全部参数化；禁止字符串拼接查询；ORM 的 raw 查询必须走参数绑定
- [ ] 输出转义，防 XSS；文件下载设置 `Content-Disposition` 与正确的 `Content-Type`
- [ ] 文件上传：校验真实 MIME（不信任扩展名）、限制大小、重命名存储、**存储在 Web 根目录之外**、必要时杀毒
- [ ] SSRF 防护：用户可控 URL 走白名单或禁止访问内网段
- [ ] 反序列化：不反序列化不可信数据到可执行结构

## 三、认证与授权

- [ ] 认证与授权分离；鉴权在**服务端强制**，前端隐藏不构成防护
- [ ] 每个端点显式声明所需权限；默认拒绝
- [ ] 越权测试覆盖**横向**（同角色访问他人资源）与**纵向**（低权限访问高权限操作）
- [ ] 会话/令牌：最短有效期、可吊销、登出即失效；敏感操作二次校验
- [ ] 限流与防爆破：登录、上传、第三方代理端点必须有独立限流

## 四、依赖与供应链

- [ ] 锁文件入库，CI 用 frozen install
- [ ] SCA 扫描：无 high 及以上（`osv-scanner`）
- [ ] 产出 SBOM（`syft` / `cyclonedx`）并随制品归档
- [ ] 第三方 GitHub Action 固定到 **commit SHA**，不用浮动 tag
- [ ] 依赖新增需人工批准（不可逆决策，走 ADR 或 PR 明确标注）
- [ ] 每月依赖巡检，结论记入 `docs/tech-stack.md`

## 五、数据保护

- [ ] 传输 TLS；静态加密开启
- [ ] PII 字段加密存储（或列级加密），分级见 `docs/data-model.md`
- [ ] 日志、埋点、错误上报全程脱敏；审计日志独立存储、不可篡改
- [ ] 导出功能受控：有权限校验、有审计、有数量上限
- [ ] 保留期与删除权实现（见 `data-model.md` 第五节）

## 六、部署与运行时

- [ ] 容器以非 root 运行；基础镜像最小化并定期重建
- [ ] 关闭生产环境调试开关、详细错误堆栈与交互式文档（或加权限）
- [ ] 安全响应头：HSTS、CSP、X-Content-Type-Options、Referrer-Policy
- [ ] CORS 白名单，禁止 `*` 携带凭证

## 七、验证动作（Gate 5 前完成）

| 验证 | 方式 | 结论 |
|---|---|---|
| 越权访问 | <用低权限账号访问他人资源，应 403> | [ ] |
| 注入 | <构造 SQL/命令注入载荷，应被拒绝且无异常泄露> | [ ] |
| 密钥泄露 | <故意提交假密钥，CI 必须红> | [ ] |
| 供应链 | <引入已知高危依赖，osv-scanner 必须红> | [ ] |
| 限流 | <压测登录端点，应 429 且不锁死合法用户> | [ ] |
| 信息泄露 | <触发 500，响应体不得含堆栈与内部路径> | [ ] |

## 八、事件响应

- 发现凭证泄露：**先吊销再排查**（不要先删 commit，历史仍在）
- 涉及用户数据的泄露：按 `PRD.md` 第 8 节的合规要求评估是否需告知与上报，时限与对象事先写清
- 每次安全事件出复盘，改进项进 `implementation-plan.md`
